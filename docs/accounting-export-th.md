# รายงานบัญชีคู่ CSV

ใช้งาน: **รายการ → ส่งออก CSV → รายงาน → ภาษาในไฟล์ → เลือกที่บันทึกไฟล์ CSV**. ค่าเริ่มต้นไทย; English เปลี่ยนหัวตาราง สถานะ ชื่อบัญชีระบบ และข้อความระบบ ชื่อบัญชี/รายละเอียดที่ผู้ใช้พิมพ์จะไม่ถูกแปล

- **สมุดรายวันทั่วไป:** วันที่ รหัสรายการ ประเภท สถานะ อ้างอิงรายการเดิม รหัสบัญชี ชื่อบัญชี เดบิต เครดิต คำอธิบาย แต่ละรายการเรียงฝั่งเดบิตก่อนเครดิต
- **บัญชีแยกประเภท:** ข้อมูลเดียวกัน จัดกลุ่มตามบัญชี พร้อมยอดคงเหลือเดบิต/เครดิตหลังแต่ละรายการ
- **งบทดลอง:** ยอดรวมเคลื่อนไหวเดบิต/เครดิต และยอดคงเหลือเดบิต/เครดิตรายบัญชี พร้อมผลรวมตรวจสมดุล

ไฟล์รวมประวัติตั้งแต่เริ่มถึงวันที่ปัจจุบัน ไม่ใช่เฉพาะเดือนที่แสดงบน dashboard วันที่ระบุ ค.ศ. แบบ YYYY-MM-DD และสกุลเงินบาท; ยังไม่มีตัวเลือกงวดปิดบัญชีหรือช่วงวันที่ ไม่แปลงยอดเริ่มต้นเป็นรายได้ ไม่กลับข้างเดบิต/เครดิตเพราะหน้าจอบัตรเครดิตแสดงหนี้เป็นบวก และไม่ตัดรายการที่ถูกยกเลิกทิ้ง: ต้องมีทั้งต้นฉบับและรายการกลับบัญชีให้ตรวจสอบได้ รายการที่ถูกลบพร้อมบัญชีจะไม่อยู่ในไฟล์ที่ส่งออกภายหลัง

ข้อมูลมาจาก postings ที่บันทึกจริง ไม่มีการให้ LLM คิดยอด กรอบการแสดง journal อ้างอิงหลักวันที่/บัญชี/คำอธิบาย/เดบิตเท่ากับเครดิตตาม [OpenStax — Journal entries](https://openstax.org/books/principles-financial-accounting/pages/3-5-use-journal-entries-to-record-transactions-and-post-to-t-accounts). รหัสบัญชีเป็น stable app IDs ไม่ใช่ผังบัญชีตามกฎหมายที่รับรองหรือเลขแบบภาษี

**ขอบเขต:** เป็นรายงานบัญชีคู่ของสมุดส่วนบุคคล ยังไม่ใช่การรับรอง TFRS/NPAEs หรือชุดงบการเงินครบตามกฎหมาย ไม่มี accrual/invoice lifecycle, tax subledgers, accounting-period lock, audit retention สำหรับการลบถาวร หรือการปิดบัญชีครบวงจร VAT และหัก ณ ที่จ่ายยังต้องเพิ่ม compound postings/หลักฐาน/กฎก่อน รายละเอียด VAT ใน bullet ของใบเสร็จเป็นข้อมูลอ่านประกอบ ไม่ทำให้เกิดบัญชีภาษีซื้อหรือภาษีขายอัตโนมัติ ดู [ข้อกำหนดภาษี](tax-engine-th.md)

- เพิ่ม 7 accounting-export tests: รายรับ/จ่าย/โอน/หนี้/ยอดเริ่มต้น/กลับรายการ, งบทดลองที่คำนวณแยกไว้, running balances, localization, empty report, ยอดเคลื่อนไหวข้ามเดือนเกินขอบเขตยอดคงเหลือ, และข้อมูลอ้างอิงไม่ครบที่ต้องปฏิเสธ
- เพิ่มข้อความ VAT+WHT ใน quick-entry rejection cases: ไม่ตัดยอดแรกจากข้อความหลายฐานมาเป็นรายการธรรมดา
- สร้างไฟล์จริงทั้ง 6 แบบจาก application + SQLite ในหน่วยความจำ ผ่าน example `export_accounting_samples` แล้วอ่านกลับด้วย PowerShell `Import-Csv` ซึ่งเป็น parser คนละตัวกับตัวเขียน ตรวจ UTF-8 BOM/byte validity, ไทย/สระ/วรรณยุกต์, quotes/comma/newline/bullets, formula protection, ยอดเคลื่อนไหว **2,170.25 = 2,170.25** และงบทดลอง **1,800.00 = 1,800.00**
- Release Windows UI: ตรวจเปิดหน้าส่งออก รายงานครบ 3 แบบ ค่าเริ่มต้นไทย เปลี่ยน English/รายงาน ยกเลิก และเปิดใหม่กลับค่าเริ่มต้น; ภาพ `.preview/accounting-export-dialog.png`. ไม่ได้ใช้ automation เลือก path ในหน้าต่าง Save ของ Windows หรือเปิด Excel desktop ในรอบนี้
- ยังไม่ได้ทดสอบ export ผ่าน Android Storage Access Framework หรือ build APK

ทำซ้ำกับโฟลเดอร์ใหม่ (example ปฏิเสธการเขียนทับไฟล์เดิม):

```sh
cargo run -p ledger-infrastructure --example export_accounting_samples --locked --offline -- .preview/accounting-exports-new
cargo test -p ledger-application --test accounting_export --locked
```

CSV ไม่มีฟอนต์ฝัง; UTF-8 ทำให้ข้อความไทยคงอยู่ โปรแกรมที่เปิดเป็นผู้เลือกฟอนต์ ถ้า Excel รุ่นเก่าเปิดแล้วอ่านผิด ให้ **Data → From Text/CSV → UTF-8 → comma** แล้วตรวจวันที่/ID เป็น text เมื่อจำเป็น ไฟล์ส่งออกนี้เป็นรายงาน ไม่ใช่ไฟล์สำรองกู้คืนฐานข้อมูลทั้งหมด
