# พอร์ต BTC / SOL ใน 0.1.2

หน้า **บัญชี → เพิ่มบัญชี → คริปโต** รับจำนวน BTC และ SOL ในพอร์ตเดียวกัน ใส่ 0 สำหรับเหรียญที่ไม่มี เปลี่ยนจำนวนภายหลังด้วย **แก้จำนวนเหรียญ** เก็บ BTC ถึง 8 ตำแหน่งและ SOL ถึง 9 ตำแหน่งเป็นจำนวนเต็มหน่วยย่อย ไม่ใช้ floating point คำนวณเงิน

สมุดบัญชี THB จะแสดงราคาประเมินจาก CoinGecko และมูลค่า `จำนวนเหรียญ × ราคา THB ต่อเหรียญ` โดยปัดยอดของแต่ละเหรียญเป็นสตางค์ก่อนรวม มูลค่าพอร์ตรวมในสินทรัพย์และสินทรัพย์สุทธิ ราคาไม่ได้เป็นราคาซื้อขายที่รับประกัน

- เรียกราคาประมาณทุก 60 วินาทีเมื่อมีพอร์ตที่ถือเหรียญและแอปทำงานอยู่ มีปุ่มอัปเดตเองและจำกัดการกดถี่
- เมื่อเครือข่ายหรือผู้ให้บริการล้มเหลว จะเว้นช่วงลองใหม่เพิ่มขึ้นถึงประมาณ 8 นาที และคงราคาที่บันทึกไว้ล่าสุด
- แสดงเวลาราคาจากผู้ให้บริการเสมอ ราคาที่เกิน 3 นาทีมีป้ายราคาเก่า เวลาในอนาคตเกิน 5 นาทีถูกปฏิเสธ
- ถ้ายังไม่เคยได้ราคา พอร์ตที่มีเหรียญจะแสดง `—` พร้อมแจ้งว่าภาพรวมยังไม่รวมพอร์ตนั้น พอร์ตว่างมีมูลค่า 0 ได้โดยไม่ต้องมีราคา
- ปิดแอปแล้วเปิดใหม่ยังมีจำนวนเหรียญและแคชราคาเดิม แต่ราคาเก่าไม่ถูกแสดงว่าเป็นราคาปัจจุบัน

API ส่งเฉพาะชื่อสาธารณะ `bitcoin`, `solana` และสกุล `thb` ไม่ส่งจำนวนเหรียญ ชื่อบัญชี เลขกระเป๋า หรือรายการการเงิน มี HTTPS และกำหนดเวลารอสูงสุด 8 วินาที งานเครือข่ายทำแยกจาก UI และตัวบันทึกบัญชี

## พอร์ตเก่าที่เคยกรอกเป็นเงินบาท

แอปคงยอดเดิมและประวัติไว้ ไม่เดาว่าเงินบาทเดิมคือจำนวนเหรียญ กด **ระบุจำนวนเหรียญ** แล้วใส่จำนวนที่ถือจริง หลังยืนยัน ภาพรวมจะใช้มูลค่าเหรียญแทนยอดพอร์ตเดิม ไม่บวกทั้งสองยอดซ้ำกัน หากบัญชีเดิมผูกกับแผนรายจ่ายประจำ ให้เปลี่ยนแผนไปใช้บัญชีเงินสดหรือธนาคารก่อน

พอร์ตจำนวนเหรียญใช้ปรับจำนวน BTC/SOL โดยตรง ไม่เป็นบัญชีสำหรับรับ จ่าย หรือโอนเงินบาท การแก้จำนวนไม่สร้างรายการรับจ่าย รายการซื้อขาย กำไรขาดทุน หรือต้นทุนทางภาษี ระบบเก็บประวัติการปรับจำนวนแยกในฐานข้อมูล

รายงาน CSV บัญชีคู่ยังเป็นข้อมูลตามสมุดบัญชีเดิม ไม่เพิ่มกำไรจากการประเมินตลาดหรือรายได้ภาษีให้อัตโนมัติ ถ้าซื้อหรือขายจริง ยังต้องบันทึกการเคลื่อนไหวเงินและข้อมูลภาษีที่เกี่ยวข้องตามข้อเท็จจริง ฟีเจอร์นี้ไม่ได้เชื่อมกระเป๋า ส่งคำสั่งเทรด หรือคำนวณภาษีคริปโต

## ขอบเขตการแก้แผนรายจ่ายประจำ

ปุ่ม **แก้ไขแผน** แสดงข้างปุ่มบันทึกจ่าย เปลี่ยนชื่อ ยอด วันชำระ บัญชี หมวด และจำนวนงวดได้ เลือกเดือนเริ่มใช้การแก้ไข ระบบหยุดเงื่อนไขเดิมตั้งแต่เดือนนั้นและสร้างเงื่อนไขใหม่ในธุรกรรมฐานข้อมูลเดียว งวดก่อนหน้าและรายการจ่ายเดิมไม่ถูกเขียนทับ

กรณีมีการจ่ายล่วงหน้า ให้เลือกเดือนหลังงวดที่เคยบันทึกจ่ายล่าสุด การแก้ไขไม่ย้ายลิงก์รายการที่จ่ายแล้ว และคำสั่งแก้ไขที่ใช้ข้อมูลเก่าจะถูกปฏิเสธให้โหลดใหม่ จำนวนงวดของเงื่อนไขใหม่เริ่มนับจากเดือนที่เลือก โดยค่าเริ่มต้นเป็นจำนวนเดือนตามสัญญาที่ยังเหลือ
