# ผลตรวจบันทึกด่วน กระแสเงินสด และภาษี — 24 กันยายน 2026

## ขอบเขตที่ทำงานจริง

- Desktop macOS: คืน native Edit menu เพื่อให้ Command-V/C/A ทำงานในช่องข้อความ ก่อนแก้ การวางภาษาไทยผ่าน clipboard ไม่เข้า textbox; หลังแก้ วางประโยคตัวอย่างและบันทึกสำเร็จ
- ประโยคไทยใน grammar ที่รองรับใช้ได้โดยไม่ดาวน์โหลดโมเดล ข้อความอิสระนอก grammar ยังใช้ local LLM และต้องมีโมเดล
- แยกครั้งละ 1–8 รายการด้วย `และ` หรือขึ้นบรรทัดใหม่; ชื่อบัญชี/โน้ตในเครื่องหมายคำพูดไม่ถูกแบ่งกลางข้อความ
- การกำหนดบัญชีท้ายประโยคสำหรับหลายรายการต้องมีจำนวนบัญชีตรงกันและ `ตามลำดับ` มิฉะนั้นให้เลือกบัญชีทุกบรรทัดเอง
- แสดงสิ่งที่ยังขาดแยกรายการ: ยอด บัญชี หมวด วันที่ หรือปลายทาง ไม่เลือกหมวดหรือสร้างบัญชีให้เอง
- ผู้ใช้เติมข้อมูลในฟอร์ม ตรวจสรุป และยืนยันทั้งชุด; SQLite transaction เดียว บันทึกทั้งหมดหรือไม่บันทึกเลย และ retry submission เดิมไม่เพิ่มรายการซ้ำ
- ยังไม่ใช่การสนทนาต่อเนื่องเพื่อรวมคำตอบข้อความรอบถัดไปเข้ากับ draft เก่า และไม่ใช่ LLM หลายรายการแบบไม่จำกัดไวยากรณ์

## กราฟกระแสเงินสด

ย้อนหลัง 6 เดือนปฏิทิน เลือกเดือนได้ ใช้วันรายการถึงวันนี้ ไม่รวมยอดตั้งต้น เงินโอน และรายการที่ยกเลิก รายการยกเลิกตัดออกจากเดือนเดิม

`rate = (รายรับ − รายจ่าย) / (รายรับ + รายจ่าย)` อยู่ระหว่าง −1 กับ +1; ถ้ายอดรวมเป็น 0 แสดง “ยังไม่มีข้อมูล” อัตราแสดงถึง 4 ตำแหน่ง และเกณฑ์สุขภาพเทียบเศษส่วนจริง ไม่เทียบค่าที่ปัดเพื่อแสดง

- แย่: rate < 0
- พอใช้: 0 ≤ rate < 0.10
- ดี: rate ≥ 0.10

เกณฑ์นี้เป็นตัวชี้วัดรายรับรายจ่ายที่เลือกสำหรับผลิตภัณฑ์ ไม่ใช่มาตรฐานกฎหมายหรือการประเมินสุขภาพการเงินครบทุกด้าน ยังไม่รวมภาระผ่อน หนี้ สภาพคล่อง และเงินสำรอง

เปอร์เซ็นต์สัดส่วนใช้ยอดรายรับ+รายจ่ายเป็นฐาน ส่วน “มากกว่า X%” ใช้ฝั่งที่น้อยกว่าเป็นฐาน แสดงชื่อฐานชัดเจน ถ้าฝั่งนั้นเป็นศูนย์จะไม่หารด้วยศูนย์

ทดสอบ: เดือนข้ามปี, ไม่มีรายการ, รับ/จ่ายอย่างเดียว, เท่ากัน, ตรงขอบ 0.10, ติดลบเล็กน้อย, ยอดใกล้เพดาน, transfers/openings/future/reversal ใน `crates/application/tests/cashflow.rs`

## การตรวจหน้าจอ Desktop จริง

ใช้แอป build จาก workspace ใน bundle ชั่วคราว และฐานข้อมูล `/private/tmp/ledgers-bro-verification-20260924` ไม่ใช้ฐานข้อมูลส่วนตัว

1. สร้างเงินสด 1,000 บาท และกรุงไทย 0 บาท
2. วางประโยคตัวอย่างผ่าน clipboard → ได้ 2 รายการ บัญชีและยอดตรง ขึ้นข้อความ “ยังขาด: หมวดหมู่” และปิดปุ่มตรวจจนเลือกครบ
3. เลือกอาหารและรายรับอื่น ๆ → หน้า preview แสดง 30/เงินสด และ 400/กรุงไทย → ยืนยันทั้งชุด
4. ภาพรวมแสดงรายรับ 400 รายจ่าย 30 เงินเหลือ 370 สินทรัพย์ 1,370; สัดส่วน 93%/7%, rate ประมาณ +0.8604, สถานะดี เลือกเดือนว่างแล้วขึ้นไม่มีข้อมูล
5. พบและแก้ select ที่ไม่แสดงบัญชีตอนสร้าง options ครั้งแรก ทดสอบซ้ำแล้วแสดงเงินสด/กรุงไทยถูกต้อง
6. ภาษีเงินเดือน 600,000 บาท ไม่มีสิทธิอื่น → ค่าใช้จ่าย 100,000 ลดหย่อนส่วนตัว 60,000 เงินได้สุทธิ 440,000 ภาษี 21,500
7. เพิ่มหัก ณ ที่จ่าย 30,000 → ต้องจ่ายเพิ่ม 0 ชำระไว้เกิน 8,500
8. เลือกกรณีที่ยังไม่รองรับ → ลบผลยอดเดิมและแสดงว่าข้อมูลยังไม่อยู่ในขอบเขตคำนวณ

## ภาษี

ชุดกฎ `TH-PIT-2568-2569-core-2026-09-24` เป็น worksheet คำนวณในขอบเขตที่ประกาศ ไม่ใช่ระบบยื่นแบบ และไม่ได้รับรองความครบถ้วนภาษีไทยทุกกรณี อ่าน [coverage catalog](tax-engine-th.md)

ชุดทดสอบ `crates/application/tests/tax.rs`: ทุกขอบขั้นอัตรา, เพดานค่าใช้จ่าย 40(1)+(2), ภาษีขั้นต่ำ/ข้อยกเว้น 5,000, minimum vs progressive, เพดานร่วมประกัน, สิทธิครอบครัว, เงินบริจาค, ประกันสังคมแยกปี, withholding/prepayment, ชำระเกิน, fractional amounts, ข้อมูลไม่ครบ/นอกขอบเขต และตัวเลขผิดรูปแบบ

ไม่มีการยิงข้อมูลไป RD e-Filing, ไม่มีผล differential comparison กับระบบยื่นจริง และไม่มีการรับรองจากผู้เชี่ยวชาญ การแสดงผลหน่วยบาท/สตางค์และเศษต่ำกว่าสตางค์ในกรณีชายขอบต้องตรวจเทียบระบบยื่นจริงเพิ่มเติมก่อนใช้เป็น filing engine

เพิ่ม padding ให้การ์ดภาษีทั้งฟอร์มและผลลัพธ์ รวมทั้งกราฟ: Desktop 24px, จอกว้างไม่เกิน 480px ใช้ 16px ตรวจภาพหน้าภาษี Desktop build ล่าสุดแล้ว
