# บันทึกด่วนและรายจ่ายประจำ — 24 กันยายน 2026

## ปัญหาและสิ่งที่แก้

ข้อความ `เมื่อวานซื้อกาแฟ 50 บาท บันทึกลง เงินสด แล้วก็วันนี้ได้เงินค่าจ้างวาดรูป 200 บาท บันทึกลงกรุงไทย` เคยถูกตัดที่ `บันทึกลง` ครั้งแรก จากนั้นส่วนที่เหลือถูกอ่านเป็นชื่อบัญชี จึงเหลือรายการเดียว

ตอนนี้แยกคำเชื่อม `และ`, `และก็`, `แล้ว`, `แล้วก็` และขึ้นบรรทัดใหม่ โดยเคารพเครื่องหมายคำพูด ก่อนจับคู่บัญชีของแต่ละรายการ รูปแบบบัญชีรวมท้ายประโยค `ตามลำดับ` ยังใช้ได้ ถ้าแยกหลายรายการไม่ครบ จะไม่ส่งต่อให้โมเดลที่รองรับเพียงรายการเดียวแล้วบันทึกเฉพาะบางส่วน

หมวดหมู่ที่ไม่ได้ระบุยังให้ผู้ใช้เลือกเอง หน้าตรวจแสดงสิ่งที่ขาดทุกบรรทัดและมีปุ่ม “ตรวจข้อมูลที่ยังขาด” ที่กดแล้วอธิบายได้ เมื่อเติมครบจะเป็นปุ่มตรวจรายการ ตามด้วยยืนยันบันทึกทั้งหมด ไม่มีการเดาบัญชี หมวด หรือยอดเงิน

## วิธีใช้รายจ่ายประจำ

1. เปิด **รายจ่ายประจำ → เพิ่มรายจ่ายประจำ** กรอกชื่อ ยอดต่อเดือน วันที่ 1–31 เดือนเริ่ม บัญชี และหมวด เลือกจำนวนงวด 1–1,200 หรือไม่กำหนด
2. เลือกงวดเดือนเพื่อดูวันครบกำหนด ยอดตามแผน ยอดจ่ายจริงที่ผูกกับงวด และยอดค้างจ่าย
3. วัน 29–31 ที่ไม่มีในเดือนนั้นใช้วันสุดท้ายของเดือน เช่น 31 กันยายน → 30 กันยายน และ 31 กุมภาพันธ์ปีอธิกสุรทิน → 29 กุมภาพันธ์
4. เมื่อจ่ายแล้ว กด **บันทึกการจ่าย / ใช้รายการเดิม** ปรับยอดจริง วันที่จ่าย และบัญชีได้ แล้วตรวจและยืนยัน
5. ถ้าเคยลงในบันทึกด่วนหรือแบบฟอร์มแล้ว เลือกรายจ่ายเดิมเพื่อผูกกับงวด ระบบไม่ลงรายจ่ายเพิ่ม รายการหนึ่งผูกได้เพียงงวดเดียว
6. ใช้ **หยุดแผนตั้งแต่งวดนี้** เมื่อต้องการยุติแผนตั้งแต่เดือนที่เลือก ข้อมูลที่จ่ายแล้วคงอยู่ หากต้องการเปลี่ยนยอดหรือวันในอนาคต ให้หยุดแผนเดิมแล้วเพิ่มแผนใหม่

แผนเกิดซ้ำตามปฏิทินในฐานข้อมูล ไม่ต้องเปิดแอปค้าง ไม่มีการหักบัญชีเงินจริง ไม่มีการสร้าง journal ว่าจ่ายแล้วอัตโนมัติ และยังไม่มี OS notification การยกเลิกรายจ่ายที่ผูกไว้ทำให้งวดนั้นกลับเป็นค้างจ่าย หากลบบัญชี แผนยังอยู่แต่ต้องเลือกบัญชีใหม่ตอนจ่าย และงวดที่รายจ่ายถูกลบจะกลับเป็นค้างจ่าย

## กราฟ Flow rate

- เปิด “รวมรายจ่ายประจำที่ยังค้างจ่าย” เป็นค่าเริ่มต้น: รายจ่ายในกราฟ = รายจ่ายที่บันทึกจริง + ยอดแผนที่ยังไม่จ่ายของเดือนเดียวกัน
- ปิดตัวเลือกเพื่อดูเฉพาะรายการจริง ยอดบัญชีและรายงานบัญชียังคำนวณจาก journal จริงเสมอ
- รายรับใช้เฉพาะยอดบันทึกแล้ว ไม่มีการสมมติเงินเดือนในอนาคต
- จ่ายเต็มงวดแล้วเอายอดตามแผนออก แล้วใช้ยอดจ่ายจริง หากจ่ายจริงต่างจากแผน ใช้ยอดจริงทั้งงวด รุ่นนี้ยังไม่แบ่งชำระบางส่วนของงวด
- จ่ายล่วงหน้าได้ รายจ่ายจริงนับในเดือนที่จ่าย และงวดอนาคตที่ผูกไว้ไม่มีค้างจ่ายเพิ่ม
- กราฟย้อนหลัง 6 เดือน ส่วนหน้ารายจ่ายประจำเลือกเดือนอนาคตได้ ไม่ยกยอดค้างของเดือนก่อนมาบวกซ้ำทุกเดือน

ตัวอย่างที่ตรวจบน Desktop: รายรับ 200 รายจ่ายจริง 50 แผนค้าง 100 → กราฟรวมรายจ่าย 150, rate `+0.1428`; ปิดโหมดรวมแผน → รายจ่าย 50, rate `+0.6000`; ยืนยันจ่ายแผน 100 → รายจ่ายจริง 150 ค้าง 0 และ rate ยังคง `+0.1428`

## การจัดเก็บและทดสอบ

- บันทึกรายจ่าย + postings + การผูกงวดใน `BEGIN IMMEDIATE` เดียวกัน ตรวจแผนและงวดซ้ำภายใต้ write lock

## จำนวนงวดและช่องทาง prompt ที่เพิ่ม

Schema v3 เพิ่มจำนวนงวดให้แผนเดิมเป็นไม่กำหนดโดยไม่แก้ประวัติ จ่ายครบทุกงวดแล้วออกจากตัวเลือกที่ยังต้องจ่าย แต่เก็บประวัติไว้ แผนที่เลยเดือนสุดท้ายแล้วยังค้างจะยังเลือกจ่ายได้ ยกเลิกการจ่ายเปิดงวดเดิมกลับมา ทั้งหน้ากรอกเองและรายการที่อ่านจาก prompt มีตัวเลือกแผน/งวด และคงยอด วันที่ บัญชีที่ระบุเองไว้

การทดสอบ native เพิ่มเติม: เปลี่ยนแผนเดิมเป็น 2 งวด แล้วใช้ prompt จ่าย 90 บาท เลือกงวดที่ 2/2 เดือนตุลาคม (ตามแผน 100) หมวดเติมจากแผน ยืนยันได้และแผนแสดงว่าจ่ายครบ ไม่สร้างภาระต่อ รายจ่ายประจำถือว่าหนึ่งรายการชำระหนึ่งงวด แม้ยอดจริงต่างจากแผน; การรับชำระลูกหนี้รองรับการแบ่งชำระบางส่วนแยกต่างหาก

Schema v4 เพิ่มลูกหนี้และเงินต้นรับคืน; v5 เพิ่ม idempotency ของคำสั่งหลายประเภท ดู [คู่มือ prompt และลูกหนี้](prompt-actions-th.md) ผลทดสอบเมื่อจบ schema v5: 160 passed / 2 ignored (OCR runtime fixtures) ผ่าน format, Clippy `-D warnings`, workspace tests และ desktop debug build รอบนี้ทดสอบ UI บน macOS เท่านั้น
