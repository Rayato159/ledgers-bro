# ทิศทางภาพ Ledgers Bro

เอกสารนี้เป็นประวัติทิศทาง v1 ซึ่งถูกแทนที่แล้ว ธีมปัจจุบันอยู่ที่ [Pastel companion](pastel-companion-theme.md) ภาพคอนเซปต์ PNG เก่าถูกนำออกจากโปรเจกต์ระหว่างจัด repository; เก็บข้อความและ prompts นี้ไว้เป็นประวัติ

ภาพ `ledgers-bro-ui-concept-v1.png` สร้างด้วย built-in imagegen จาก original art ของผู้ใช้และภาพ UI เกม เป็นคอนเซปต์ bitmap สามหน้าจอ: ภาพรวม, เพิ่มรายจ่าย, ตรวจใบเสร็จ มีข้อมูลตัวอย่าง ยังไม่ใช่หน้าจอแอปที่รันได้หรือไฟล์ UI ที่แก้แต่ละ component ได้

**ทิศทางที่เลือกสำหรับตัวอย่าง**

ใช้ตัวละครผมดำแว่นกลม เสื้อดำแขน/คอ plaid กีตาร์แดงเป็นลายเซ็น แผง UI สีขาวอุ่น ขอบหมึกเข้ม เงา offset เล็กน้อย หัวข้อ/ปุ่มทรงเฉียง halftone ชมพูและพื้นม่วงหม่น เส้นตัวอักษร/ตัวเลขเนื้อหายังคงตรงและอ่านง่าย

Palette ตั้งต้น: paper `#F5F1EC`, ink `#24232B`, pink `#F16B95`, lavender `#AAA0BE`, teal `#369B99`, yellow `#F4C54E` ใช้เป็นทิศทาง ไม่ใช่ชุดสีที่ผ่าน accessibility contrast audit แล้ว

เสนอฟอนต์ไทยที่มีน้ำหนักสำหรับ UI เช่น Noto Sans Thai โดยตรวจ license และ bundle ไฟล์ไว้ในแอป ไม่โหลดจาก CDN ในเวลาใช้งาน ตัวเลขใช้ tabular figures ในฟอนต์ที่รองรับ ไม่ใส่ texture หลังยอดเงินหรือหมายเหตุ

**แนวทาง implement**

- พื้นผิว ปุ่ม panels และ halftone สร้างด้วย CSS/SVG ของแอป ตัวละครเป็น assets แยก ห้ามใช้ภาพเต็มหน้าจอเป็น UI เพราะกด/อ่านด้วย screen reader/ขยายตัวอักษรไม่ได้
- มาสคอตใหญ่ใช้เฉพาะ onboarding/empty state/ความสำเร็จที่เหมาะสม หน้ากรอกเงินจริงย่อ header เพื่อให้เห็น amount/account/category/Save เมื่อ keyboard เปิด
- ใช้ icon family ชุดเดียวสำหรับค่าเช่า อาหาร ของกินเล่น ของฟุ่มเฟือย ของใช้ รักษาพยาบาล หนี้ และอื่นๆ พร้อม label ไทยที่อยู่ใน DOM ไม่ฝังข้อความใน icon
- ใช้สีร่วมกับข้อความและรูปทรง: รายรับ/รายจ่ายต้องแยกได้แม้มองไม่เห็นสี แจ้งข้อมูลไม่พอด้วยข้อความ ไม่ใช้เพียง icon
- UI จริงต้องมีวันที่ของรายการ ตัวเลือกบัญชี เปลี่ยนหมวด รายละเอียด และ feedback ว่าบันทึกแล้ว/ยังเป็น draft
- Pinch/ระบบขยายข้อความ, VoiceOver/TalkBack, safe areas, keyboard, focus และ reduce motion ต้องอยู่ใน acceptance tests
- ภาพ AI ไม่ใช่ตัวแทนด้าน accessibility, ความแม่นข้อมูล หรือ screenshots สำหรับ Store ก่อนมีฟีเจอร์จริง

**สิ่งที่ต้องแก้จาก mockup ก่อนทำหน้าจอจริง**

ข้อมูลและวงกราฟในภาพเป็นตัวอย่างจาก image generation ไม่ใช่ fixture ที่ reconcile แล้ว ต้องคำนวณกราฟจาก ledger จริงและตรวจ total/percentage ภาพมีหมวดเดินทางเป็น sample ที่เพิ่มระหว่าง generation; default category list ของสเปกยังคง 8 หมวดที่ผู้ใช้ให้มา

ชื่อ category ทางการต้องใช้ “รักษาพยาบาล” ให้ตรงสเปก ไอคอนหมวดหนี้ไม่ควรทำให้สับสนกับปุ่มเพิ่มหนี้/ชำระเงินต้น ข้อความ “อ่านบนเครื่อง” ต้องแสดงหลัง runtime ทำงาน local จริงเท่านั้น

หลักการสื่อสาร: ตัวละครเป็นเพื่อนช่วยจัดการเงิน ไม่ตัดสินผู้ใช้ว่าเป็นคนไม่ดีเมื่อใช้เงินเยอะ สถานะการเงินต้องมีเหตุผลและทางตรวจข้อมูล ยึดการอ่านยอดและบันทึกทันเวลาเป็นงานหลัก

**การแทนที่ด้วย Art ของผู้ใช้**

แยกชื่อ assets ตาม role เช่น mascot-dashboard, mascot-empty, mascot-saved, category-food; เก็บ original drawing และ editable master ของผู้ใช้แยกจาก export PNG/WebP/SVG เพื่อเปลี่ยนภาพได้โดยไม่เปลี่ยนกฎบัญชี ตรวจขอบโปร่งใส สัดส่วน หน้าจอเล็ก และความชัด 1x/2x/3x ก่อนใส่ release

รูป Shopee ถูกตัดออกจาก reference และ prompt ไม่มี asset จากรูปนั้น ภาพอาวุธไม่ถูกนำมาใช้ในคอนเซปต์นี้ ภาพ final สำหรับ Store ควรใช้ screenshots จาก app build จริง
